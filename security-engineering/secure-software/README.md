# Secure Software

My principles / methodology

Things like:

* secure software design
* threat modeling
* input validation
* authentication / authorization
* dependency security
* secure coding
* security testing
* supply-chain security
* defensive engineering

> Security engineering covering threat modeling, application security, security analysis, incident investigation, and recovery.

I build software with security in mind from the beginning, rather than treating security as a final review before release.

I also work on the other side of the boundary: understanding what happened when a system is attacked or fails, investigating the cause, and helping make the system safer afterward.
